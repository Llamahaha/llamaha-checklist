Fast File Downloads with Start-BitsTransfer / BITS

Safe copy/paste patterns for reliable file downloads in PowerShell, CMD, and Datto RMM remote command contexts.

Overview

Why use BITS

Plain-English meaning

Start-BitsTransfer uses Windows Background Intelligent Transfer Service to download files. It is often more reliable than a browser download in remote support because it can handle large files, network interruptions, and explicit destination paths.

Use cases

  • Download an installer, diagnostic bundle, agent package, or cleanup utility to a remote endpoint.
  • Place a file in a predictable path such as C:\ProgramData\Temp or C:\Windows\Temp.
  • Run from a Datto RMM Agent Browser command or PowerShell context when the user is not at the keyboard.

Warning

Only download from trusted, approved URLs. Do not paste private package URLs, credentials, SAS tokens, license keys, or customer-specific download links into this guide or public ticket notes.

PowerShell Examples

Local or remote PowerShell

Simple download

$Source = "<URL>"
$Destination = "C:\ProgramData\Temp\<FILENAME>"
New-Item -ItemType Directory -Path (Split-Path $Destination) -Force | Out-Null
Start-BitsTransfer -Source $Source -Destination $Destination

TLS 1.2 and logging

[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$Source = "<URL>"
$Destination = "C:\ProgramData\Temp\<FILENAME>"
$Log = "C:\ProgramData\Temp\bits-download.log"
New-Item -ItemType Directory -Path (Split-Path $Destination) -Force | Out-Null
"$(Get-Date -Format s) Starting download from $Source to $Destination" | Out-File -FilePath $Log -Append
Start-BitsTransfer -Source $Source -Destination $Destination -ErrorAction Stop
"$(Get-Date -Format s) Download complete. Size: $((Get-Item $Destination).Length) bytes" | Out-File -FilePath $Log -Append

Asynchronous job with status

$Job = Start-BitsTransfer -Source "<URL>" -Destination "C:\ProgramData\Temp\<FILENAME>" -Asynchronous
while (($Job.JobState -eq "Connecting") -or ($Job.JobState -eq "Transferring")) {
  Start-Sleep -Seconds 2
  $Job = Get-BitsTransfer -JobId $Job.JobId
}
if ($Job.JobState -eq "Transferred") {
  Complete-BitsTransfer -BitsJob $Job
} else {
  $Job | Format-List *
  Remove-BitsTransfer -BitsJob $Job
  throw "BITS download failed."
}

Datto RMM Examples

Agent Browser and online agent commands

PowerShell context

[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$Destination = "C:\ProgramData\Temp\<FILENAME>"
New-Item -ItemType Directory -Path (Split-Path $Destination) -Force | Out-Null
Start-BitsTransfer -Source "<URL>" -Destination $Destination -ErrorAction Stop
Get-Item $Destination | Select-Object FullName, Length, LastWriteTime

CMD-compatible command that launches PowerShell

powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "[Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12; $d='C:\ProgramData\Temp\<FILENAME>'; New-Item -ItemType Directory -Path (Split-Path $d) -Force | Out-Null; Start-BitsTransfer -Source '<URL>' -Destination $d -ErrorAction Stop; Get-Item $d | Select FullName,Length,LastWriteTime"

When command context is SYSTEM

  • Use machine-wide paths such as C:\ProgramData\Temp or C:\Windows\Temp.
  • Do not download to %USERPROFILE% unless you know which user context is running.
  • Network shares may fail under SYSTEM unless computer-account permissions and network authentication are designed for it.
  • After downloading as SYSTEM, remember file ownership and permissions may differ from an interactive user download.

Common Symptoms

Failure points and fast checks

Common failures

  • URL requires an interactive login, cookie, or expiring token.
  • Endpoint cannot reach the host because of DNS, proxy, content filtering, or firewall policy.
  • Old PowerShell or .NET defaults do not negotiate TLS 1.2 without setting SecurityProtocol.
  • Destination folder does not exist or the running context lacks write access.
  • Execution policy blocks a larger script. A one-line command can use -ExecutionPolicy Bypass when policy allows.

Fast checks

  • Test DNS with Resolve-DnsName <HOSTNAME> or nslookup <HOSTNAME>.
  • Confirm the destination folder exists and the downloaded file size is nonzero.
  • Check Get-BitsTransfer -AllUsers for stuck jobs if run with admin rights.
  • Remove failed jobs with Remove-BitsTransfer after capturing error details.

Cleanup

Remove-Item -LiteralPath "C:\ProgramData\Temp\<FILENAME>" -Force
Remove-Item -LiteralPath "C:\ProgramData\Temp\bits-download.log" -Force -ErrorAction SilentlyContinue
Get-BitsTransfer -AllUsers | Where-Object DisplayName -like "*<OPTIONAL_NAME>*" | Remove-BitsTransfer

What To Gather Before Escalation

Evidence package

Collect

  • Command used, with private URL tokens redacted.
  • Destination path, running context, and whether it was Datto RMM, local PowerShell, or CMD.
  • Error text from BITS, PowerShell, or Datto RMM job output.
  • DNS/proxy/firewall test results and endpoint hostname.
  • Whether the URL works from another network and whether it needs authentication.
