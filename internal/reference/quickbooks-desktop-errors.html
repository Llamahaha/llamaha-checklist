QuickBooks Desktop Error Reference

Runbook for two common QuickBooks Desktop company-file errors: (-6000, -77) and the "company file already open" message.

Safety

Before changing company files

Warning

QuickBooks company files are business-critical accounting data. Before renaming support files, changing hosting, moving files, repairing data, or running utilities, confirm a recent backup exists and get approval from the responsible business contact or accounting owner.

Baseline evidence

  • QuickBooks edition/year/release, Windows computer/server name, and user/session context.
  • Company file name and whether it is local, UNC, mapped drive, RDS/hosted desktop, or server share.
  • Exact error text and screenshot.
  • Whether other users can open the same file and whether multi-user mode is expected.

Error (-6000, -77)

Problem opening the company file

Plain-English meaning

QuickBooks cannot open the company file from its current location. The failure usually points to file path, permissions, network access, hosting, or QuickBooks support-file issues rather than a simple username/password problem.

Likely causes

  • Company file path is too long, unavailable, blocked, or referenced by a mapped drive that does not exist in the current session.
  • Windows share or NTFS permissions prevent the user or QuickBooks Database Server Manager from accessing the file.
  • .ND or .TLG support files are damaged or stale.
  • Hosting/multi-user mode is enabled on the wrong workstation or disabled on the server that should host the file.
  • Firewall, security software, file lock, server issue, or disconnected VPN blocks the company file.

Fast checks

  • Open QuickBooks without opening a company file by holding Ctrl while launching, then browse to the file.
  • Try the UNC path instead of a mapped drive, for example \\<SERVER>\<SHARE>\<FILE>.qbw.
  • Confirm the same Windows user can browse to the folder, create a temporary test file if approved, and read the company file path.
  • Ask whether any server reboot, migration, QuickBooks update, backup restore, or file move happened recently.
  • Check whether the QuickBooks Database Server Manager sees and scans the company file folder on the host.

Fix steps

  1. Confirm there is a current backup or business approval before changing files.
  2. Update QuickBooks Desktop to the approved release if the issue started after an update mismatch.
  3. Open the company file from a UNC path instead of a mapped drive.
  4. If approved, rename matching .ND and .TLG files by adding .OLD to the end so QuickBooks can recreate them.
  5. Check hosting: only the server or correct host should host multi-user access unless the environment is designed otherwise.
  6. Run QuickBooks File Doctor or repair tools only after recording the current state and confirming backup posture.

Escalation notes

Escalate if multiple users are blocked, the server share is unstable, the company file may be damaged, File Doctor reports data problems, backups are missing, or accounting staff cannot approve file changes.

Already Open Message

QuickBooks already has a company file open

Plain-English meaning

The user is trying to open another company file while a company file is already open in a QuickBooks edition or context that does not allow that workflow.

Why this happens

  • QuickBooks Pro or Premier generally expects one company file open at a time.
  • QuickBooks Accountant and QuickBooks Desktop Enterprise support a secondary company file workflow, but with restrictions.
  • A hidden QuickBooks window, stuck process, RDS session, or hosted desktop session already has a file open.
  • The user launched a second QuickBooks shortcut instead of closing the current file or using the supported secondary-file path.

How to confirm

  • Check the QuickBooks title bar for the current company file name.
  • Use Window menu options inside QuickBooks to find open windows or switch company context.
  • On RDS/hosted desktops, check whether the same user has another disconnected session with QuickBooks open.
  • Check Task Manager for stuck QBW32.exe processes only after confirming QuickBooks is not actively being used.

Fix steps

  1. Save work and close open QuickBooks windows.
  2. Use File > Close Company or Logoff, then open the intended company file.
  3. If the edition supports it and the workflow is approved, use the documented "Open Second Company" path instead of File > Open or Restore Company.
  4. For RDS/hosted environments, sign out disconnected duplicate sessions or ask hosting support to clear the stale user session.
  5. If QuickBooks is hung, end the process only after confirming no unsaved user work is at risk.

Escalation notes

Escalate if the user needs a multi-company workflow not supported by their edition, hosted sessions keep leaving orphaned QuickBooks processes, multiple users report file lock issues, or there is risk of unsaved accounting work.

What To Gather Before Escalation

Evidence package

Collect

  • Exact error screenshot and timestamp.
  • QuickBooks product edition/year/release and whether Accountant or Enterprise is involved.
  • Company file path type and whether it is local, UNC, mapped drive, hosted desktop, or RDS.
  • Backup status before any file repair, rename, move, or hosting change.
  • List of affected users, whether one user can open the file, and whether multi-user mode is expected.
  • Any recent server, share, VPN, QuickBooks, or file migration change.
