Playbook (Skeleton)

New PC deployment with ImmyBot

Internal-only. The repeatable path for taking a new workstation from the box to a fully deployed, signed-in machine using ImmyBot. This is a skeleton; expand each section with the exact tenant, naming, and approval details for the customer when documenting per-customer playbooks.

Before You Touch the Machine

Pre-deployment checklist

Confirm the request and the customer

Ticket has the user's full name, work email, customer/tenant, role/department, computer use case (admin, CAD, finance), and any "must-have" apps beyond the standard role profile.

Confirm the hardware

Make/model, asset tag, serial number, and MAC address logged in the RMM and the customer's asset list. Charge the device and connect to wired or known-good Wi-Fi before the build starts.

Pick the right ImmyBot deployment template

Each customer in ImmyBot should have a baseline deployment plus role-specific deployments (CAD, finance, exec). Pick the template that matches the user's role; if no role-specific template exists, document the gap and start from the baseline plus a manual app list.

Stage accounts and licenses

User exists in Microsoft 365 / customer tenant with the right license assignments before deployment. Any product-specific accounts (Autodesk, Adobe, Bluebeam, ArcGIS, ROCK, Innovyze) are assigned to the user before the build runs the licensing-dependent steps.

Step 1

OOBE and ImmyBot agent install

Boot through the minimum OOBE

Boot the PC, work through Out-of-Box Experience to the desktop using a temporary local account (or Autopilot if the customer is on Autopilot). Connect to network. Do not sign in with the end-user account at OOBE.

Install the ImmyBot agent

Either via Autopilot enrollment (preferred where configured) or by manually downloading the customer's ImmyBot tenant agent from the ImmyBot portal and running it on the device. Confirm the device appears in ImmyBot under the right customer/tenant.

Confirm the device is registered to the customer in ImmyBot

Wrong tenant assignment is the most common early mistake. Verify the device is under the correct customer in ImmyBot before triggering deployment.

Step 2

Run the ImmyBot deployment

Assign the deployment

In ImmyBot, assign the role-appropriate deployment to the device. Confirm the deployment includes: AV/EDR, RMM agent, AutoElevate, browser baseline, Microsoft 365 Apps, Teams, OneDrive, VPN client, password manager, and any role-specific software (CAD, finance, GIS, etc.).

Trigger and monitor

Run the deployment from ImmyBot. Watch the deployment session live for the first run on a new template; long-running installs (Autodesk, ArcGIS, Adobe CC) should be expected to take time but not fail. Check the ImmyBot session log for any task that errors, retries, or is skipped.

Re-run failed tasks before manual installs

If specific software fails, re-run just that task in ImmyBot before falling back to a manual install. ImmyBot will surface the failure reason; resolving the underlying cause keeps future deployments clean.

Step 3

User sign-in and personalization

First sign-in with the end user account

Sign in with the user's work account. Complete Windows Hello / MFA prompts. Confirm BitLocker is enabled and the recovery key is escrowed where expected (Entra/Azure AD or the customer's chosen escrow).

Validate the core stack

Open Outlook (mail loads), Teams (signed into right tenant), OneDrive (syncs), browser (right profile), and the RMM/EDR agents are reporting. Test print to one default printer if applicable.

Validate role-specific apps

Open each role-specific app, sign in with the assigned account, and run one minimum smoke test (open a known file, run a simple action). Document any app that needs additional setup the user will have to finish on first use.

Migrate user data if applicable

If replacing an existing PC, run the documented data-migration procedure (OneDrive Known Folder Move, profile copy via tooling, manual transfer for niche apps). Confirm completion before retiring the old machine.

Step 4

Handoff and documentation

Log the build in the RMM and asset list

Update the device record: assigned user, build date, deployment template used, BitLocker recovery key location, any deviations from the standard.

Send the user a welcome packet

Quick-start with sign-in instructions, MFA setup, AutoElevate prompt explanation, where to file tickets, and a link to the customer-facing help center.

Schedule a 7-day follow-up

Brief check-in to catch any "missed" software, printer config, or shared-drive access that did not surface on day one.

Update the deployment template if needed

If a manual install was required, decide whether to add it to the customer's ImmyBot template so the next deployment is cleaner. Keep skeleton playbook in sync with the template.

Common Issues

What goes sideways and how to recover

Device shows up in the wrong customer/tenant in ImmyBot

Caused by running the wrong tenant's agent. Remove the device from ImmyBot, uninstall the agent, install the correct customer's agent, and re-register before deployment.

Deployment hangs on a long install

Some apps (Autodesk Suite, ArcGIS Pro, full Adobe CC) genuinely take 30+ minutes. Check the ImmyBot session log for actual progress vs. a real hang. If hung, cancel the task, capture the log, and re-run.

License assignment failed at install time

Usually means the user license was not assigned in the vendor portal before the deployment ran. Assign the license, sign the user in to the app, and confirm activation. Note the gap so the pre-deployment checklist catches it next time.

Software installed but user cannot launch it

Check whether the install is per-machine or per-user, and whether the install ran under the right context. Some vendor installers expect the end user to sign in once to complete entitlement; document this on the welcome packet.
